Cart Referral Tracking for WooCommerce

Technical Assessment submission · Custom plugin “UID Cart Referral Tracker” v1.0.0 · {{DATE}}

1. Summary

A custom WordPress plugin, written from scratch, that:

  • detects ?uid_temp=STRING_ID on any page and stores it in the browser’s localStorage, where it stays available on every page the visitor opens afterwards;
  • reads the code back from localStorage on every add-to-cart (single-product form submit, shop/archive AJAX buttons, plain add-to-cart links and block/Store API requests) and logs the event into a custom table;
  • shows the log under WooCommerce → Cart Referrals with tracking code, product, quantity, price, source, customer, linked order and timestamp, plus filters, search, sorting, bulk delete and CSV export.

Plugins used: no referral or affiliate plugin was used. The only third-party components are WooCommerce 11.2.1 (the store itself, as required) and the free Storefront 4.6.2 theme. All tracking logic lives in the custom plugin documented below.

2. How it works

A. Capture & persist (frontend)

  1. The plugin enqueues assets/js/uct-tracker.js on every frontend page, together with a nonce created by wp_create_nonce().
  2. On page load the script reads uid_temp from the URL with URLSearchParams, strips control and markup characters, limits it to 100 characters and saves it with localStorage.setItem('uid_temp', value). A newer shared link replaces an older code (last click wins).
  3. Because localStorage is per-origin, the code stays available on every later page, tab and visit until the visitor clears site data.
  4. The script also mirrors the value into a first-party cookie (uct_uid_temp, SameSite=Lax, 30 days). The cookie is only a fallback for WooCommerce block/Store API requests, whose JSON body cannot be extended. localStorage stays the source of truth: the cookie is rewritten from it on each page view.

B. Cart tracking (backend & database)

Add-to-cart pathHow the code is sent from localStorageLogged as
Single-product page form submitHidden inputs uid_temp and uct_nonce are injected into form.cart in a capture-phase submit listener.form
Shop/archive AJAX buttonsThe adding_to_cart jQuery event receives WooCommerce’s request data object by reference; the code and nonce are added to it. A $.ajaxPrefilter covers other jQuery add-to-cart calls from themes or quick-view plugins.ajax
Plain ?add-to-cart=ID links (AJAX disabled)A click listener appends uid_temp and uct_nonce to the link before navigation.link
Block themes / Store APIServer reads the cookie mirror.store_api

On the server, one hook handles all four paths: woocommerce_add_to_cart, which fires once for every successful add. The handler:

  1. reads $_REQUEST['uid_temp'] and accepts it only when wp_verify_nonce() passes, otherwise falls back to the cookie mirror;
  2. sanitizes with wp_unslash() and sanitize_text_field(), and truncates to 100 characters;
  3. takes a snapshot of the product name, SKU and price, and records the quantity, source, user, WooCommerce session, IP, user agent, referrer and both local and GMT timestamps;
  4. inserts the row with $wpdb->prepare().

When the visitor checks out (classic or block checkout), the code is saved on the order as _uid_temp, shown on the order edit screen, and the matching log rows get their order_id filled in.

C. Admin dashboard

WooCommerce → Cart Referrals requires the manage_woocommerce capability. It shows summary cards, the top five codes and a WP_List_Table. The table has search by code or product, filters by source and date range, sorting on whitelisted columns, pagination, a nonce-checked bulk delete and a nonce-checked CSV export.

3. Security

RequirementImplementation
Input sanitizationsanitize_text_field( wp_unslash() ) for the code, user agent and filters; absint() for IDs and quantities; sanitize_key() for order and sort keys; dates validated against a regex; esc_url_raw() for the referrer. The client side also cleans the value before storing it.
Prepared queriesEvery INSERT, UPDATE, DELETE and filtered SELECT uses $wpdb->prepare(). LIKE searches use $wpdb->esc_like(). Sort columns and directions are whitelisted.
NoncesThe frontend sends uct_nonce with every add-to-cart and the server checks it with wp_verify_nonce(), which blocks cross-site forged attribution. The nonce action does not start with “woocommerce”, so guest nonces stay stable before and after the WooCommerce session starts. Bulk delete uses check_admin_referer('bulk-referrals') and CSV export uses check_admin_referer('uct_export').
Output escapingAll admin output goes through esc_html, esc_attr or esc_url. The CSV export neutralises cells starting with = + - @ to prevent formula injection.
Access controlThe admin page, bulk delete and export all check current_user_can('manage_woocommerce').

5. Installation

  1. Copy the uid-cart-tracker folder into wp-content/plugins/, or upload uid-cart-tracker.zip under Plugins → Add New → Upload.
  2. Activate WooCommerce, then activate “UID Cart Referral Tracker”. Activation creates the table {prefix}uid_cart_referrals.
  3. Share any store URL with ?uid_temp=CODE appended, add products to the cart, then open WooCommerce → Cart Referrals.
  4. Deleting the plugin from the Plugins screen drops the table (uninstall.php).

By default only add-to-carts that carry a code are logged, since the page is a referral log. Developers can log every add-to-cart with add_filter( 'uct_log_without_uid', '__return_true' );. On sites with full-page caching, cached pages can serve an expired nonce after 24 hours. In that case the cookie fallback still attributes the event.
